# 磁盘写满与文件句柄耗尽

## 现象

- 服务日志突然停止输出，或报 `No space left on device`
- 新连接建立失败，报 `Too many open files`
- 写文件、写日志全部失败，但读接口正常

## 排查步骤

1. `df -h` 看磁盘使用率，确认是哪个分区
2. `du -sh /*` 逐层找大目录，通常是 `/var/log` 或临时文件
3. `lsof | wc -l` 看句柄总数
4. `ulimit -n` 看单进程限制
5. 检查是否有日志没做轮转（logrotate 配置）

## 常见根因

| 根因 | 典型证据 |
|---|---|
| 日志没有轮转 | 单个日志文件几十 GB |
| 临时文件堆积 | `/tmp` 下大量旧文件 |
| 句柄泄漏 | 连接 / 文件打开后没有关闭 |
| core dump | 目录下有大量 `core.*` |

## 处置动作

- 紧急：删掉最老日志（确认已归档），或 `truncate` 而不是 `rm`（rm 后句柄没释放，空间不回收）
- 治本：配置 logrotate，按大小 + 天数双条件轮转
- 句柄泄漏：重启止血，同时修代码；调大 `ulimit` 只是缓兵之计

## 注意

`rm` 一个正在被写的日志文件，磁盘空间不会立刻释放——进程还持有句柄。要用 `truncate -s 0`。
