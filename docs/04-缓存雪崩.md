# 缓存雪崩 / 击穿 / 穿透

## 三种情况的区别

| 名字 | 含义 | 典型场景 |
|---|---|---|
| 雪崩 | 大量 key 同时过期 | 凌晨批量预热，TTL 设成一样 |
| 击穿 | 单个热点 key 过期 | 首页 banner、秒杀商品 |
| 穿透 | 查不存在的数据，缓存永远不命中 | 恶意请求随机 ID |

## 现象

- 缓存命中率从 95% 掉到 20%
- 数据库 QPS 突然涨 10 倍
- 接口 P99 上升，但 CPU 不算高（在等数据库）

## 排查步骤

1. 看缓存命中率曲线，是否断崖下跌
2. 看数据库 QPS 是否同步上涨
3. 检查是否在整点 / 凌晨集中过期
4. 检查是否有大量查不存在 ID 的请求

## 处置动作

- 雪崩：给 TTL 加随机偏移（如 30 分钟 ± 5 分钟），并做热点预热
- 击穿：热点 key 用互斥锁重建，或逻辑过期（不设物理 TTL）
- 穿透：空值也缓存（短 TTL）+ 布隆过滤器

## 兜底

数据库前面加一层限流，防止缓存全挂时把数据库打死。
