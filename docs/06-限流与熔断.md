# 限流与熔断误触发

## 现象

- 大量请求返回 429 / 503
- 上游服务报 `rate limit exceeded` 或 `circuit breaker is open`
- 实际流量并没有暴涨

## 排查步骤

1. 看限流规则：QPS 阈值多少、按什么维度（IP / 用户 / 接口）
2. 看被限流的请求特征：是否来自同一个 IP、同一个用户
3. 看熔断器状态：错误率阈值、半开状态是否卡住
4. 检查是否有重试风暴：客户端重试把流量放大

## 常见根因

| 根因 | 典型证据 |
|---|---|
| 阈值设太低 | 正常流量下就有 429 |
| 单 IP 刷接口 | 429 集中在少数 IP |
| 重试风暴 | 同一请求在日志里出现 3 次以上 |
| 熔断未恢复 | 错误率已降但熔断器仍在 open |

## 处置动作

- 阈值不合理：评估真实峰值后调整，不要拍脑袋
- 单 IP 刷：加黑名单或验证码
- 重试风暴：客户端加指数退避 + 抖动，服务端做幂等
- 熔断卡住：手动重置熔断器，检查半开探测是否正常

## 原则

限流是保护，不是惩罚。误伤正常用户的限流，比不加限流更糟。
